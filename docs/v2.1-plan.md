# Fon Pusulası 2.1 — development plan

Baseline: production-tested Fon Pusulası 2.0 release branch. Development must stay on `feature/fon-pusulasi-v2-1` until acceptance.

## Priorities
1. Portfolio performance clarity: distinguish realized, unrealized and total returns; avoid implying returns when transaction or price history is missing.
2. Fund and stock comparisons: consistent periods and explicit as-of dates; no fabricated observations.
3. Compact UI: retain accessible tap targets and existing controls while reducing unnecessary whitespace.
4. Data freshness: surface source timestamps, missing history and retry errors clearly.
5. Reliability: cache integrity, offline handling, startup and navigation regression tests.

## Release gates
- Existing production regression suite remains green.
- New features have focused automated tests.
- No change to production Android package/signing identity.
- Verify that updating the installed app preserves portfolio data.
- Validate fund one-year chart and date range on an Android device.
- Publish a signed 2.1 APK only after acceptance; keep 2.0 available for rollback.

## Scope discipline
Do not silently change scoring formulas, portfolio return methodology, source priority or stored transactions. Document and test any intentional migration. No new features are shipped to the live branch before verification.
